## Architecture

LoanGuard is an AI financial advisory platform. Loan credit analysis is one sub-module of a larger
React + FastAPI + Supabase system. See `docs/architecture.md` for the full system diagram.

The ML pipeline (owned by ML engineer):

```
Raw Applicant Data (17 raw features, string categoricals)
    → [Preprocessing] LabelEncode → Compute 4 Ratios → StandardScale  → 20 features
    → [Stage 1] Isolation Forest   → anomaly_flag
    → [Stage 2] XGBoost Classifier → risk_score [0–1], decision
    → [Stage 3] Interest Rate      → rate [5%–20%] (approved only)
    → [SHAP]   per-request         → shap_top3 (why this decision?)
    → [DiCE]   if rejected         → counterfactuals (what would change it?)
```

**Notebooks** (run sequentially — each feeds the next):
- `01_EDA.ipynb` — exploration of `data/raw/Loan_default.csv` (255,347 records)
- `02_preprocessing.ipynb` — LabelEncoder (7 categorical cols) → `data/interim/loans_cleaned.csv`
- `02b_feature_engineering.ipynb` — 4 financial ratios + train/test split + StandardScaler (13 numerical cols) → `data/processed/`
- `03_xgboost_risk_model.ipynb` — XGBoost training; optimal threshold 0.4885, ROC-AUC 0.7595, 20 features
- `04_isolation_forest.ipynb` — contamination=0.05, flags ~4.94% of test records
- `05_interest_rate_optimization.ipynb` — documents linear/sigmoid/quadratic rate mapping; hardcoded threshold (0.6491) is stale, use metadata
- `06_dice_counterfactual.ipynb` — DiCE-ML counterfactual generation; demonstrates `DiceExplainer` usage

**Trained artifacts** in `models/`:
- `label_encoders.joblib` — dict of {col: LabelEncoder} for 7 categorical columns (fit on raw strings)
- `scaler.joblib` — StandardScaler fit on 13 numerical columns: 9 original + 4 ratios (from 02b)
- `xgboost_risk_model.joblib` + `xgboost_metadata.json` — optimal_threshold: 0.4885, 20 features
- `isolation_forest.joblib` — anomaly detector

**Implemented `src/` modules:**
- `src/pipeline/interest_rate.py` — `compute_interest_rate(risk_score, ...)` linear/sigmoid/quadratic
- `src/models/predictor.py` — `LoanGuardPredictor.predict(dict) → dict` (full pipeline, lazy SHAP)
- `src/explainability/shap_explainer.py` — `SHAPExplainer.explain_top_n(df, n)` per-request SHAP
- `src/explainability/dice_explainer.py` — `DiceExplainer.generate_counterfactuals(dict)` DiCE-ML

**Stub modules** (structure only): `src/api/`, `src/data/`, `src/features/`.

## Inference Pipeline Order

Must apply in this exact order (or use `LoanGuardPredictor` which handles it):
1. `label_encoders.joblib` → encode 7 categorical cols (string → int)
2. Compute 4 ratios: LoanToIncome, PaymentToIncome, CreditAgePerLine, TotalDebtBurden (annuity formula)
3. `scaler.joblib` → transform 13 numerical cols (9 original + 4 ratios)
4. Feed all 20 features to Isolation Forest and XGBoost

## Configuration

`configs/model_params.yaml` holds hyperparameters for all three stages. `models/*_metadata.json`
files store the parameters actually used at training time (source of truth). The threshold in
`xgboost_metadata.json` (0.4885) is authoritative — ignore any hardcoded values in notebooks.

## Data

Dataset (`data/raw/Loan_default.csv`) is not committed — shared via Google Drive. Processed splits
in `data/processed/` and interim in `data/interim/` are also excluded. Target variable (Default)
is heavily imbalanced (~11.6% default), handled via `scale_pos_weight=7.6` in XGBoost.

## Reports

`reports/metrics/` contains JSON performance metrics. `reports/figures/` contains PNG visualizations
generated by notebooks (prefixed `xgb_*`, `if_*`, `ir_*`, `dice_*`, `02b_*`).
